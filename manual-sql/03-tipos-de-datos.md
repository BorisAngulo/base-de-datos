# 3. Tipos de datos

El tipo es el **dominio** de la columna: qué valores acepta. El CSV no tiene
tipos; el motor sí, y los aplica en cada `INSERT`/`UPDATE`.

## 3.1. Números

| Uso | PostgreSQL | MySQL | Notas |
|-----|------------|--------|-------|
| Entero | `INTEGER` / `INT` | `INT` | 32 bits de sobra para un `id` |
| Entero chico | `SMALLINT` | `SMALLINT` | |
| Entero grande | `BIGINT` | `BIGINT` | |
| Dinero / decimales exactos | `NUMERIC(10,2)` | `DECIMAL(10,2)` | **No uses `FLOAT` para precios** |
| Aprox. científico | `REAL`, `DOUBLE PRECISION` | `FLOAT`, `DOUBLE` | Redondeo binario |

`NUMERIC(10,2)` = 10 dígitos en total, 2 después del punto: `12345678.90`.

```sql
-- Ambos motores
precio  NUMERIC(10, 2) NOT NULL
stock   INTEGER NOT NULL
```

Un `'GRATIS'` en `precio` produce error de tipo
(PostgreSQL `22P02`, MySQL `1366` / `1292`).

## 3.2. Texto

| Uso | PostgreSQL | MySQL |
|-----|------------|--------|
| Cadena ilimitada | `TEXT` | `TEXT` |
| Cadena con tope | `VARCHAR(n)` | `VARCHAR(n)` |
| Cadena fija | `CHAR(n)` | `CHAR(n)` | Rellena con espacios; casi nunca hace falta |

En PostgreSQL `TEXT` y `VARCHAR` se comportan igual salvo el tope.
En MySQL elige `VARCHAR(n)` para nombres (`VARCHAR(120)`) y `TEXT` para
descripciones largas.

## 3.3. Booleanos y fechas

| Uso | PostgreSQL | MySQL |
|-----|------------|--------|
| Verdadero/falso | `BOOLEAN` (`true`/`false`) | `TINYINT(1)` o `BOOLEAN` (alias de tinyint) |
| Fecha | `DATE` | `DATE` |
| Hora | `TIME` | `TIME` |
| Fecha y hora | `TIMESTAMP` | `DATETIME` |
| Con zona horaria | `TIMESTAMPTZ` | no hay equivalente limpio; se suele guardar UTC en `DATETIME` |

```sql
-- PostgreSQL
activo     BOOLEAN NOT NULL DEFAULT TRUE
creado_en  TIMESTAMPTZ NOT NULL DEFAULT NOW()

-- MySQL
activo     BOOLEAN NOT NULL DEFAULT TRUE
creado_en  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
```

## 3.4. NULL

`NULL` significa “desconocido / no aplica”. No es `0` ni `''`.

```sql
SELECT 1 = NULL;          -- NULL, no FALSE
SELECT 1 IS NULL;         -- FALSE
SELECT NULL IS NULL;      -- TRUE
```

Para comparar con nulos usa `IS NULL` / `IS NOT NULL`, nunca `= NULL`.

## 3.5. Autonumérico (próximo capítulo)

El `id` que se genera solo:

| PostgreSQL | MySQL |
|------------|--------|
| `GENERATED BY DEFAULT AS IDENTITY` (moderno) | `INT AUTO_INCREMENT` |
| o `SERIAL` (clásico, crea una secuencia) | |

Se declara en el `CREATE TABLE` del [capítulo 4](04-tablas-y-restricciones.md).

## 3.6. Regla práctica

- Identificadores: `INTEGER` (o `BIGINT` si esperas millones de millones).
- Dinero y cantidades exactas: `NUMERIC` / `DECIMAL`, nunca `FLOAT`.
- Nombres: `TEXT` (PostgreSQL) o `VARCHAR(n)` (MySQL).
- “¿Existe o no?”: `BOOLEAN`.
- Instantes: `TIMESTAMPTZ` (PostgreSQL) / `DATETIME` en UTC (MySQL).
